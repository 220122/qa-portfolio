## 环境

同 BUG-001。

## 复现步骤

```python
import requests
r = requests.post("http://127.0.0.1:8000/api/chat", json={"question": "   "}, timeout=30)
print(r.status_code, r.text)
```

## 预期结果

状态码 400（或直接拒答且不落评测记录），提示"提问内容不能为空"。

## 实际结果

```
200 {"question":"   ","answer":"当前课程知识库中没有该知识点，无法作答。","retrieved":false,"refused":true,
     "evaluation":{"id":"20261108231152330802","timestamp":"2026-11-08 23:11:52","question":"   ",
     "retrieved":false,"refused":true,"chunk_summaries":[],"answer":"当前课程知识库中没有该知识点，无法作答。"}}
```

请求被当作**正常问题**处理：走完检索流程、写入一条评测记录。

## 影响

1. 空白提问污染评测数据：`/api/evaluations` 里堆积无意义记录，影响后续质量统计（误拒答率等指标会被拉高）
2. 语义不正确：无意义输入被归因为"知识库没有该知识点"，掩盖了"入参不合法"这一真实原因
3. 若前端可被绕过，接口层没有任何防线

## 定位线索

`backend/schemas.py`：

```python
class ChatRequest(BaseModel):
    question: str = Field(..., min_length=1)
```

`min_length=1` 只能挡住空字符串，挡不住 `"   "`（长度 3）。校验层没有 `strip()`。

## 建议修复

```python
from pydantic import BaseModel, Field, field_validator

class ChatRequest(BaseModel):
    question: str = Field(..., min_length=1)

    @field_validator("question")
    @classmethod
    def _not_blank(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("提问内容不能为空")
        return v
```

## 关联观察（不作为缺陷，仅记录）

同一个课内问题 `文件的物理结构有哪几种？`：

- 23:09 手工调用 → 被拒答
- 23:12 自动化用例（同一问题）→ 正常作答

两次调用相隔 3 分钟、知识库未变，结果不一致 → 说明检索/拒答判定存在**偶发不稳定**。建议按 R-10 建立固定评测集，用误拒答率量化，而不是靠单次调用判断。
