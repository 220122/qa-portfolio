# BUG-005 课内问题误拒答率 20%（4/20），用户问教材内知识被告知"没有该知识点"

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-005 |
| 所属项目 | course-rag-agent |
| 关联脚本 | `api-tests/check_golden_set.py` + `data/golden_set.json`（30 条评测集） |
| 关联风险项 | R-10（拒答阈值依赖一次性校准） |
| 严重程度 | 一般 |
| 优先级 | 高 |
| 状态 | 已量化，待定位与调优 |

## 环境

同 BUG-001。当次配置：`RELEVANCE_THRESHOLD=0.43`、`TOP_K=8`、`CHUNK_SIZE=500`、向量模型 `BAAI/bge-small-zh-v1.5`、对话模型 `deepseek-flash`、知识库为《计算机操作系统》教材（docx 1167 块 + pdf 1224 块）。

## 复现步骤

1. 启动后端，知识库已导入教材
2. 依次提问 20 条课内问题与 10 条课外问题（见 `api-tests/data/golden_set.json`）
3. 用固定拒答话术「没有该知识点」判定是否被拒

```bash
cd api-tests && python check_golden_set.py
```

## 预期结果

- 课内问题应正常作答（误拒答率接近 0）
- 课外问题应全部拒答（漏拒率 0）

## 实际结果

| 指标 | 实测值 |
|---|---|
| 误拒答率 | **20.0%（4/20）** |
| 漏拒率 | **0.0%（0/10）** |

4 条误拒答明细：

| 用例 | 问题 | 结果 |
|---|---|---|
| G-06 | 进程调度有哪些常见算法？各自的优缺点是什么？ | 返回拒答话术 |
| G-10 | SPOOLing 技术的作用是什么？ | 返回拒答话术 |
| G-15 | inode 中存储了哪些信息？ | 返回拒答话术 |
| G-17 | 什么是写时复制（COW）？ | 返回拒答话术 |

这 4 个知识点在教材中**均有覆盖**（进程调度算法、SPOOLing、inode、写时复制都是操作系统教材的核心章节）。

## 影响

1. 用户问的是自己上传的资料，却被答复"知识库中没有该知识点"——**核心功能实质性失效**，且误导性强（用户会以为自己没传对资料）
2. 20% 的误拒意味着：每 5 个真实课内问题就有 1 个答不出来，但这个问题**不会以报错形式暴露**，只会被用户投诉"答不出来"
3. 该指标**无监控**：`/api/evaluations` 只记录 refused 布尔值，没有误拒答率的聚合与告警

## 性质判断（重要）

这是**调优取舍问题**，不是代码 bug：

- 当前漏拒率 0% → 阈值偏严，防编造做得好
- 但代价是 20% 误拒 → 阈值偏严过头

因此修复方向不是"简单调大阈值"，而是：

1. **先查这 4 条为什么没召回**：把 `TOP_K` 临时调大、打印召回片段的相似度距离，确认是「距离刚好超阈值」还是「检索完全没命中」
   - 若是距离接近阈值（如 0.44~0.50）→ 阈值可上调到 0.50~0.52（README 中曾校准为 0.52）
   - 若检索没命中 → 是切块或 embedding 质量问题，调阈值无效
2. **调阈值必须带评测集回归**：把阈值从 0.43 扫到 0.55，每档记录误拒答率 / 漏拒率，画出两个指标的交叉点，取拐点而非拍脑袋
3. 增加同义/口语化问题的召回兜底（查询改写或混合检索）

## 建议的验收标准

调整后必须同时满足：**误拒答率 < 5% 且 漏拒率 = 0%**，并把这两个指标写入回归报告（`check_golden_set.py` 的输出）。
