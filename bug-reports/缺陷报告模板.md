# 缺陷报告模板

> 一份合格的缺陷报告，标准是：**开发不用来问你任何一句话，就能复现。**

---

## 模板（复制后填写）

```
标题：<模块>-<场景>-<现象>      （一句话说清，禁止写"页面有问题"）
所属项目：
缺陷编号：
环境：<浏览器/版本> / <操作系统> / <环境：测试 or 预发 or 线上> / <账号>
前置条件：<需要什么数据或状态>
复现步骤：
  1.
  2.
  3.
预期结果：
实际结果：
附件：<截图 / 录屏 / 日志 / 请求与响应 / traceId>
严重程度：<致命 / 严重 / 一般 / 轻微>
优先级：<高 / 中 / 低>
是否必现：<必现 / 偶现（X/Y 次）>
备注：<初步定位线索，例如"疑似文档解析环节未处理表格结构">
```

---

## 实例（可直接对照写）

```
标题：实验报告批阅-上传含表格的 Word 文档后，批阅结果丢失表格内容
所属项目：实验报告批阅助手
缺陷编号：BUG-003
环境：Chrome 131 / Windows 11 / 测试环境 / 账号 test01
前置条件：已登录，账号具备批阅权限
复现步骤：
  1. 进入「报告批阅」页面
  2. 上传含 3 行表格的 word.docx（见附件1）
  3. 等待生成完成，查看批阅意见
预期结果：批阅意见中包含对表格数据的评价
实际结果：批阅意见完全忽略表格内容，且页面无任何提示；将表格手工复制为文字后重新上传则正常
附件：录屏.mp4、原文档.docx、结果截图.png
严重程度：一般    优先级：高
是否必现：必现（3/3）
备注：疑似文档解析环节未处理表格结构，建议优先排查解析模块
```

## 写缺陷报告的 5 个常见错误

1. **标题含糊**："登录有问题" → 应该是"登录-输入正确密码-点击登录后仍停留在登录页且无错误提示"
2. **步骤不可复现**：漏了"需要哪个账号/哪份文件/什么前置数据"
3. **预期与实际混在一起写**：必须分两行，否则开发看不出你认为哪里错了
4. **没附件**：能截图绝不口述，能录屏绝不截图
5. **严重程度定错**：记住经典反例——首页公司名错别字：严重程度**低**、优先级**高**；千分之一机型闪退：严重程度**高**、优先级**低**

## 严重程度 vs 优先级速查

| | 高优先级 | 低优先级 |
|---|---|---|
| **高严重程度** | 主流程崩溃、资损、数据错误、安全漏洞 → 立刻修 | 罕见机型闪退、极端参数下的崩溃 |
| **低严重程度** | 首页文案/logo 错误、对外可见的低级错别字 | 深层页面的样式偏移、罕见的文案不一致 |
