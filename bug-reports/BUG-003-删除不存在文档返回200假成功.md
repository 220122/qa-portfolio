# BUG-003 删除不存在的文档返回 200 "删除成功"（假成功）

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-003 |
| 所属项目 | course-rag-agent |
| 关联用例 | `test_documents.py::test_delete_nonexistent_document` |
| 关联风险项 | R-01 |
| 严重程度 | 一般 |
| 优先级 | 高 |
| 状态 | 已复现，待修复 |

## 环境

同 BUG-001。

## 复现步骤

1. 后端已启动
2. 取一个**一定不存在**的 `doc_id`，直接调用删除接口：

```python
import requests
r = requests.delete("http://127.0.0.1:8000/api/documents/not_exist_123456", timeout=15)
print(r.status_code, r.text)
```

## 预期结果

- 状态码 **404**，`detail` 提示"文档不存在"
- 或至少返回业务失败标识，让调用方知道没有删除任何东西

## 实际结果

```
200 {"message":"删除成功","doc_id":"not_exist_123456"}
```

## 影响

1. **假成功**：前端会提示"删除成功"、把该行从列表移除，但服务端什么都没做——用户以为已删除，刷新后又出现
2. 掩盖问题：误删失败、`doc_id` 传错、前端 id 错乱等场景全部被"成功"吞掉，线上无法从接口层发现
3. 破坏接口语义：同一接口对"存在"与"不存在"返回完全一致的结果，调用方无法判断结果

## 定位线索

`backend/main.py`：

```python
@app.delete("/api/documents/{doc_id}")
def remove_document(doc_id: str):
    rag_service.delete_document(doc_id)      # 无返回值校验、无存在性判断
    return {"message": "删除成功", "doc_id": doc_id}
```

`rag_service.delete_document()` 内部对不存在的 id 静默返回，接口层据此无条件返回成功。

## 建议修复

1. 删除前先查询存在性，不存在则 `raise HTTPException(404, "文档不存在")`
2. 或让 `rag_service.delete_document()` 返回受影响条数，接口层据此决定 200 / 404
