# BUG-001 上传文件名可路径穿越，文件被写入上传目录之外并成功入库

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-001 |
| 所属项目 | course-rag-agent |
| 关联用例 | `api-tests/test_documents.py::test_upload_path_traversal_filename` |
| 关联风险项 | R-03 |
| 严重程度 | **严重**（安全类） |
| 优先级 | **高** |
| 状态 | 已复现，待修复 |

## 环境

Windows 11 / Python 3.12.7 / 后端 `uvicorn main:app --port 8000` / 上传目录 `backend\data\uploads`

## 前置条件

后端已启动，知识库已存在课件。

## 复现步骤

1. 准备任意合法的 `.docx` 文件（本次使用 `backend\操作系统课程知识库.docx`，45.9 KB）
2. 构造上传请求，把 `filename` 设为 `../../evil.docx`：

```python
import requests
with open("操作系统课程知识库.docx", "rb") as f:
    r = requests.post(
        "http://127.0.0.1:8000/api/documents/upload",
        files={"file": ("../../evil.docx", f, "application/vnd.openxmlformats-officedocument.wordprocessingml.document")},
        timeout=120,
    )
print(r.status_code, r.text)
```

3. 查看 `backend\data\uploads` 的**上一级目录**是否有文件落盘

## 预期结果

返回 4xx（拒绝非法文件名），或服务端用 `doc_id`/`uuid` 重命名落盘，原始文件名仅作为元数据保存。

## 实际结果

- 返回 **200**，响应体：`{"message":"上传并入库成功","document":{"doc_id":"c1ff1cde-160e-4f4f-94de-28176d13805b","filename":"../../evil.docx","chunk_count":28}}`
- 文件被写到 **upstream 之外**：`backend\evil.docx`（45.9 KB，2026-11-08 23:12:01）
- 该文档还成功入了向量库（28 个切块），可被检索与问答

## 影响

- 可写入任意**可写目录**的文件（本机验证为 `backend\`，再多一级 `../` 即可到任意位置）
- 覆盖同名的配置文件/脚本即可能进一步利用（如覆盖 `.env`、启动脚本）
- 攻击面：该接口不需要鉴权（见 R-08），一旦服务对外暴露即可被利用

## 定位线索

`backend/main.py` →

```python
save_path = os.path.join(settings.upload_dir, file.filename)
with open(save_path, "wb") as buffer:
    shutil.copyfileobj(file.file, buffer)
```

`file.filename` 完全来自请求，未经任何清洗即参与路径拼接。

## 建议修复

1. 落盘文件名改为服务端生成：`f"{uuid.uuid4().hex}{ext}"`；原始 `filename` 只写元数据
2. 对 `filename` 做 `os.path.basename()` 清洗，并校验落盘路径仍在上传目录内（`Path.resolve().is_relative_to(upload_dir)`）
3. 管理类接口补鉴权（见 R-08）
