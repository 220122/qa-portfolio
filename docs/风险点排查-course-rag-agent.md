# 风险点排查记录 · course-rag-agent

> 本文件是**代码评审阶段的静态风险排查**：从接口契约与实现代码推断出的可疑点，逐条给出位置、验证方法、定级建议与修复建议。
> 状态说明：`待验证` = 尚未复现；只有实际复现并留证的项才升级为缺陷报告（见 `bug-reports/`）。

---

## R-01 删除不存在的文档返回 500 而非 404

- **位置**：`backend/main.py` → `remove_document()`，直接调用 `rag_service.delete_document(doc_id)`，无存在性校验
- **现象推断**：对不存在的 `doc_id` 调用时，业务层若抛异常会被 FastAPI 兜成 500
- **验证方法**：`DELETE /api/documents/not_exist_123456`，观察状态码
- **期望**：404（资源不存在）；错误提示可读，不暴露堆栈
- **定级建议**：严重程度 一般 / 优先级 中 —— 调用方无法区分"参数错"与"服务故障"，影响重试策略
- **修复建议**：删除前先查询，不存在则 `raise HTTPException(404, "文档不存在")`

## R-02 上传接口只校验扩展名，不校验文件真实内容

- **位置**：`backend/main.py` → `ALLOWED_EXTENSIONS = {".pdf", ".docx"}`，仅比较后缀
- **现象推断**：把纯文本改名为 `.docx` 上传，解析阶段失败后被包装成 500
- **验证方法**：上传内容为纯文本、文件名为 `伪装.docx` 的文件；再上传 `%PDF-1.4` 伪造头的 `.pdf`
- **期望**：400 并提示文件内容非法（用户输入错误属客户端错误，不是服务端异常）
- **定级建议**：严重程度 一般 / 优先级 高 —— 错误码语义错误会让前端无法给出正确引导
- **修复建议**：校验文件头 magic number（docx 为 ZIP 的 `PK\x03\x04`，pdf 为 `%PDF-`）

## R-03 上传文件名直接拼接存储路径（路径穿越）

- **位置**：`backend/main.py` → `save_path = os.path.join(settings.upload_dir, file.filename)`
- **风险**：`filename` 完全来自请求，含 `../` 时可写到上传目录之外，甚至覆盖配置文件
- **验证方法**：`filename` 传 `../../evil.docx` 上传后，检查 `upload_dir` 上级目录是否出现该文件
- **期望**：拒绝（400）或服务端重命名落盘，原始文件名仅存为元数据
- **定级建议**：**严重程度 严重 / 优先级 高**（安全类）
- **修复建议**：用 `doc_id` 或 `uuid4()` 生成存储文件名，`filename` 只写进数据库元数据

## R-04 健康检查不反映依赖状态

- **位置**：`backend/main.py` → `/api/health` 硬编码 `return {"status": "ok"}`
- **风险**：向量库不可写、模型或 API Key 失效时仍返回 ok，负载均衡会继续放量
- **验证方法**：把 `CHROMA_DIR` 指向不可写目录 / 让 `DEEPSEEK_API_KEY` 失效后重启，再调 `/api/health`
- **期望**：返回非 200 或带 `degraded` 字段说明具体依赖异常
- **定级建议**：严重程度 一般 / 优先级 中 —— 影响可观测性与故障自愈
- **修复建议**：健康检查内做轻量依赖探测（Chroma 心跳、模型可用性），并区分 liveness / readiness

## R-05 提问长度无上限

- **位置**：`backend/schemas.py` → `question: str = Field(..., min_length=1)`，只有下限
- **风险**：超长文本直接进模型，费用与延迟不可控，极端情况触发上游报错
- **验证方法**：`{"question": "<5000 字>"}`
- **期望**：明确的长度上限与 400 提示
- **定级建议**：严重程度 一般 / 优先级 中
- **修复建议**：加 `max_length`（如 500），并对超限返回可读提示

## R-06 纯空格提问可通过校验

- **位置**：同 R-05，`min_length=1` 不拦空白字符
- **验证方法**：`{"question": "   "}`
- **期望**：400 或直接拒答，不消耗模型调用
- **定级建议**：严重程度 轻微 / 优先级 中
- **修复建议**：入参处 `question.strip()` 后再校验非空

## R-07 同名文件重复上传可能产生重复向量

- **风险**：同一课件多次上传后，检索 Top-K 被重复片段挤占，导致"检索到了却答不全"
- **验证方法**：同一 `docx` 连传两次，观察 `/api/documents` 是否出现两条、问答是否召回重复片段
- **期望**：按内容哈希去重，或明确提示"已存在"
- **定级建议**：严重程度 一般 / 优先级 中
- **修复建议**：入库前计算文件哈希做去重，或按文件名覆盖

## R-08 全站接口无鉴权

- **位置**：`backend/main.py` 未挂任何鉴权依赖
- **风险判断**：若定位为"本地个人工具"，属**已知限制**；若对外网暴露，则任何人均可删除知识库
- **验证方法**：不带凭证调用 `DELETE /api/documents/{doc_id}`
- **定级建议**：取决于部署形态 —— 内网/本地：不列缺陷；公网：严重 / 高
- **修复建议**：至少加 API Key 或基础鉴权中间件；管理类接口走内网

## R-09 并发提问可能出现答案串台

- **风险**：若 `rag_service` 使用了模块级共享状态（如共享的检索上下文），并发时答案可能错位
- **验证方法**：并发发起 5 个不同问题的 `/api/chat`，核对每条答案与问题是否对应
- **期望**：各自独立、无串台、无 500
- **定级建议**：若成立：严重程度 严重 / 优先级 中
- **修复建议**：确保请求级上下文隔离，不在模块级保存会话态

## R-10 拒答阈值依赖一次性校准，换模型或换资料后失效

- **来源**：`README` 第十节记录阈值 `0.52` 基于「课内距离 0.16~0.36 / 课外 0.51~0.70」实测；换 `embedding` 模型或更换学科资料后分布会漂移
- **验证方法**：换一份不同学科的课件，问该学科课内问题，统计误拒答率
- **期望**：阈值调整有回归基线支撑，而非一次性调参
- **定级建议**：属**设计风险**，不是代码缺陷
- **改进建议**：建立固定的评测集（课内/课外各若干条），每次改切块参数、换模型、调阈值都跑一遍，对比误拒答率与漏拒率

> **实测补充（2026-11-08，阈值 0.43 / TOP_K=8 / bge-small-zh / 2391 块）**：
> 20 条课内问题的最近距离为 **0.1501~0.3844**，10 条课外问题为 **0.3511~0.7019**，重叠区仅 `[0.3511, 0.3844]`（涉 3 条样本：课内 G-07/G-17、课外 G-27）。
> 说明：阈值 0.43 在**检索层**已让全部课内问题通过（0% 误拒）；端到端 20% 的误拒答来自模型层提示词，与阈值无关。
> 结论：**重叠区只由 3 条样本造成，不应据此调参**；调阈值前应先把评测集扩到每章节若干条。
