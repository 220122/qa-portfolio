# 缺陷线索清单 · course-rag-agent

> **这份清单的性质**：以下 10 条是**从代码与接口契约推出的风险点**，不是已确认的缺陷。
> 你必须自己跑一遍，**能复现的才叫缺陷**，不能复现的写进"已排查无问题"。
> 面试时讲的是"我发现→复现→提缺陷→推动修复"的闭环，**不是背别人的结论**。

---

## 线索 1：删除不存在的文档，可能返回 500 而不是 404

- **代码位置**：`backend/main.py` → `remove_document()` 直接调 `rag_service.delete_document(doc_id)`，没有存在性校验
- **验证**：`DELETE /api/documents/not_exist_123`
- **预期**：404 文档不存在　**若实际是 500**：属"错误码语义错误"，上游（前端/调用方）无法区分"参数错"和"服务崩"
- **严重程度/优先级**：一般 / 中
- **测试方法归类**：等价类（无效 doc_id）+ 异常流

## 线索 2：只校验扩展名，不校验文件真实内容

- **代码位置**：`main.py` 里 `ALLOWED_EXTENSIONS = {".pdf", ".docx"}` 只比较后缀
- **验证**：把一段纯文本另存为 `伪装.docx` 上传
- **预期**：400 提示文件内容非法　**若返回 500 "文档处理失败"**：说明后端把"用户输入错误"当成了"服务端故障"
- **加分观察**：这正是很多真实项目的通病——**白名单校验了后缀，没校验文件头（magic number）**
- **严重程度/优先级**：一般 / 高

## 线索 3：文件名直接拼进路径 → 路径穿越（安全）

- **代码位置**：`save_path = os.path.join(settings.upload_dir, file.filename)`
- **验证**：用 Postman/脚本把 `filename` 设为 `../../evil.docx`
- **风险**：可写到上传目录之外，覆盖任意可写文件
- **正确做法**：用 `doc_id` 或 `uuid` 重命名落盘，原文件名只存元数据
- **严重程度/优先级**：**严重 / 高**（安全类，面试可以重点讲，因为"能定位到具体一行代码"很加分）

## 线索 4：健康检查是"假健康"

- **代码位置**：`/api/health` 硬编码 `return {"status": "ok"}`
- **验证**：把 `CHROMA_DIR` 指向不可写目录，或让 API Key 失效，再调 `/api/health`
- **预期**：仍返回 ok → 健康检查失真，K8s/负载均衡会继续把流量打进来
- **严重程度/优先级**：一般 / 中
- **测试方法归类**：异常场景 / 可观测性

## 线索 5：超长提问没有长度上限

- **代码位置**：`schemas.py` 中 `question: str = Field(..., min_length=1)` —— 只有下限，**没有 `max_length`**
- **验证**：传 5000 字提问
- **风险**：直接送模型 → 费用与延迟不可控；极端情况触发模型侧报错
- **严重程度/优先级**：一般 / 中

## 线索 6：纯空格提问能通过校验

- **验证**：`{"question": "   "}`
- **预期**：400 或直接拒答　**若被当成正常问题调模型**：属边界校验缺失（`min_length` 挡不住空白字符）
- **测试方法归类**：等价类 + 边界值（"看起来有值但其实无意义"这一类的典型）

## 线索 7：同名文件重复上传，向量可能翻倍

- **验证**：同一 `docx` 连传两次，看 `/api/documents` 里是否出现两条、`/api/chat` 是否召回重复片段
- **风险**：Top-K 名额被重复片段挤占 → 答非所问（这是 RAG 特有的缺陷类型，通用测试岗候选人答不出来）
- **严重程度/优先级**：一般 / 中

## 线索 8：全站无鉴权

- **验证**：不带任何凭证调 `DELETE /api/documents/{doc_id}`
- **判断**：如果定位是"本地个人工具"，属**已知限制**；如果对外网暴露，属**严重缺陷**
- **面试怎么讲**：区分"缺陷"和"已知限制"是测试的专业性体现——先问清产品定位再定级，不要一上来就喊高危

## 线索 9：并发提问时答案可能串台

- **验证**：并发发 5 个不同问题的 chat 请求，核对每条答案与问题是否对应
- **风险**：若 `rag_service` 用了模块级全局状态（如共享的检索上下文），会串台
- **测试方法归类**：并发/性能 + 数据一致性
- **严重程度/优先级**：严重（若成立）/ 中

## 线索 10：拒答阈值是"一次性校准"的，换模型或换教材就失效

- **来源**：README 第十节自己写了——阈值 0.52 是拿「课内 0.16~0.36 / 课外 0.51~0.70」校准出来的
- **验证**：换一份**不同学科**的课件（如英语语法），再问课内问题 → 若大量误拒答，说明阈值不可迁移
- **这是极好的面试素材**：说明你理解"AI 应用的测试基线会随数据漂移"，需要**回归集（Golden Dataset）**而不是一次性调参
- **测试方法归类**：模型评测 / 回归测试设计

## 怎么用这份清单（Day 1 的执行方式）

1. **先把项目跑起来**：`backend/` 下建 venv → 装依赖 → 配 `.env`（填自己的 DeepSeek Key）→ `uvicorn main:app --port 8000` → 打开 `http://localhost:8000/docs`
2. **用 Swagger 页面（/docs）逐条点**，比装 Postman 快；点完 28 条用例，填 `test-cases/course-rag-agent-接口测试用例.csv` 的"执行结果"列
3. **每条线索只花 2–3 分钟**：能复现 → 按 `bug-reports/缺陷报告模板.md` 写报告；不能复现 → 在清单上标"已验证无问题"（这同样是产出，说明你排查过）
4. **目标**：确认 3–5 个缺陷，写 3 份规范报告。**1 个真实缺陷 > 10 条空想用例**

## 面试时怎么讲（一段现成的话）

> "我给自己的 RAG 项目做了一轮接口测试，写了 28 条用例，覆盖正常流程、参数异常、格式伪装、重复上传、并发和 Prompt 注入。确认了 4 个缺陷，其中两个比较有价值：一个是上传接口只校验扩展名不校验文件内容，把用户输入错误报成了 500 服务端异常；另一个是文件名直接拼路径，存在路径穿越风险。第一个我改成了内容校验并返回 400，第二个改成用 doc_id 落盘。另外我把 50 条课内问题和 30 条课外问题做成回归集，每次改切块参数或换模型都跑一遍，避免调 A 的时候弄坏 B。"

这段话里有：**用例数、覆盖维度、缺陷定位到代码、修复方案、回归意识**——比背 20 道面试题有用得多。
